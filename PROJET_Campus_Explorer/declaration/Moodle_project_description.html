1. Project overview

Campus Explorer is an Android application that helps students find their way around a university campus: lecture buildings, libraries, cafeterias and study areas.

The application shows a campus map with a few points of interest, displays the user's position, and can record a walk as a tracking session.

We build it in Java with XML layouts in Android Studio. The map uses OpenStreetMap data, displayed with Leaflet.js inside an Android WebView. The project covers the main topics of the course: Activities, Intents, the Activity lifecycle, a background service, GPS as a sensor, location services and user interface design.

2. Problem and motivation

New students often do not know where buildings and services are on campus. Campus Explorer gives them a simple map with a short list of useful places. The application shows campus points of interest and lets users follow their position while they walk.

3. Main objectives

  • Display a campus map with predefined points of interest.
  • Show basic information about a selected place.
  • Display the user's current location once permission is granted.
  • Start and stop a location-tracking session.
  • Manage the Activity lifecycle correctly and navigate between screens.
  • Keep a tracking session running in a background service when the app is no longer visible, only if the user started it.

Course conceptHow Campus Explorer uses it
Activities and IntentsThree Activities, one per main screen. Explicit Intents are used for navigation, and the identifier of a selected place is passed as an Intent extra.
Activity lifecycleonCreate(), onResume(), onPause() and onStop() are implemented and tested. The map screen manages UI-related location updates according to its lifecycle and refreshes its state in onResume().
Background serviceA foreground service records location updates during an active tracking session, even when the user switches to another app or turns off the screen. A persistent notification indicates that tracking is active and provides a way to stop it.
SensorGPS is used as the sensor to obtain the device's geographical position and monitor location changes during a tracking session.
Location and mapsAndroid location APIs and runtime permissions are used to obtain the user's position. OpenStreetMap tiles are displayed using Leaflet.js in a WebView, with the user's location shown on the map.
Local dataPredefined campus places are included in the application. Saved places and tracking-session summaries can be stored locally using SharedPreferences or SQLite.

5.1 Background service

The user starts and stops tracking explicitly. While a session is active, the service shows a persistent notification with the session status and a Stop action. When the session ends, the service stops location updates and releases its resources.

[FIGURE 3: insert fig3_tracking.png here]

Figure 3: A tracking session, from Start to Stop

The service follows Android's rules for foreground services and location permissions, and never runs when no session is active. Its lifecycle is independent of the map Activity: leaving the map screen does not stop a session the user started.

5.2 Location and maps

Location permission is requested only when the user needs it. If permission is denied or location is unavailable, the map still shows the predefined campus places.

7. Privacy and permissions

  • Location permission is requested when the user opens a feature that needs it, with a short explanation of why.
  • Background tracking starts only after a user action and is always shown by a notification. The user can stop it at any time.
  • Location data stays on the phone. No account, no personal data, nothing sent to a server.
  • A denied permission or unavailable GPS location never makes the application crash.

The final application will show a working campus map, navigation between three Activities, GPS-based location access, GPS as the selected sensor, and a background tracking service, with correct lifecycle management, permission handling and resource cleanup.
